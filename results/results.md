## RQ3 — Performance

**Limits.** Every run of every engine has the same limits: 12 GB of memory and 10 min of wall time. A run over a limit is stopped: the solution is *not viable* at that size, and is neither replayed nor tried at a larger size. Runs measured before the limits were set are classified the same way, from their peak memory and time.

**Provisional timings.** Measured on FAYOL-LEFRANCOI (Intel(R) Xeon(R) W-11955M CPU @ 2.60GHz, 16 CPUs, 62.0 GB RAM, Ubuntu 24.04.5 LTS; openjdk version "21.0.13.0.3" 2026-10-24; Python 3.12.3) on 2026-11-15T20:24:28, while other jobs were running (load average 2.57/1.47/1.66 before, 4.08/2.13/1.88 after): to be re-measured on a quiet machine.

Cold processes, best of the runs (wall time, start-up included) and the peak resident memory of that run; distinct triples of the output. ✓: the output is the reference output (Morph-KGC) at the smallest scale; =: same number of distinct triples as the reference at a larger scale; ✗: it differs (see the notes). Java engines: same JDK, same maximum heap.

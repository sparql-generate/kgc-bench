## RQ1 — Conformance to the RML test suites

Each case is solved twice by a SPARQL-Generate engine: by a hand-written query (`conformance/hand/`, mode `hand`), and by the query that `rml2sparql-generate` generates from the case's mapping (mode `translated`); an RML engine runs the mapping itself (mode `rml`), with its default options and N-Quads output, in a directory that holds the mapping and the case's input documents. A case passes when the output is isomorphic to the expected output (RDF dataset isomorphism, named graphs and RDF-star quoted triples included) and every expected target file (RML-IO) is written and isomorphic, or, for a case that expects an error, when an error is raised: a non-zero exit code, a timeout, the memory cap, or an error in the log, the same rule for every engine. A feature that the engine or the translator does not support is a failure; an engine that refuses it with an error does pass the cases of that feature that expect an error (in rml-lv, 10 of the 41 cases expect one). N/A (mode `hand` only): an invalid mapping has no hand-written counterpart, and the module suites (rml-io, rml-fnml, rml-cc, rml-star, rml-lv) have no hand-written queries. Graph maps are translated into `GRAPH` blocks of the `GENERATE` template (SPARQL-Generate 2.4.0 and later), whose output, in N-Quads, is compared graph by graph.

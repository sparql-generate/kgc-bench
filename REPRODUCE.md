# Reproducing the results

## 0. Prerequisites

- Python ≥ 3.10, `git`, `curl`, GNU `time` (`/usr/bin/time`), a systemd user session
  (every engine runs in a memory-capped scope, see README, "Memory safety");
- JDK 21 (all Java engines; SPARQL-Generate 2.2 needs ≥ 17) and Maven 3.8, paths in
  `versions.env` (`JAVA_HOME_BENCH`, `JAVA_HOME_BUILD`); JDK 11 for RMLStreamer
  (`JAVA_HOME_RMLSTREAMER`: Flink 1.14 runs on Java 8 and 11 only);
- network access for `fetch_engines.sh`, which downloads the pinned Node.js 20 and installs
  RocketRML with its `npm ci`; FlexRML is a prebuilt Linux x86-64 binary;
- `zstd` (compressed sort spills of the output fingerprints), `taskset` (util-linux), and
  the unixODBC library `libodbc.so.2` (Debian, Ubuntu: `libodbc2`), which `pyodbc` (a
  dependency of SDM-RDFizer here) loads: without it, SDM-RDFizer is not available;
- Docker usable without sudo: the SQL conformance cases (PostgreSQL, MySQL, SQL Server
  containers pinned in `versions.env`; Morph-KGC on SQL Server also needs the Microsoft ODBC
  Driver 18 for SQL Server on the host), and to generate GTFS-Madrid-Bench data at new
  scales.

```sh
python3 -m venv ~/.venvs/kgc-bench && . ~/.venvs/kgc-bench/bin/activate
pip install -r requirements.txt
# pysparql-generate in a venv of its own, never in the harness's: pysparql-generate 0.4.2
# needs DuckDB >= 2, Morph-KGC 2.10 pins DuckDB 1.x, and one install breaks the other
python3 -m venv ~/.venvs/pysg && ~/.venvs/pysg/bin/pip install "pysparql-generate[sql]==0.4.2"
export KGC_BENCH_PYSG_PYTHON=~/.venvs/pysg/bin/python
./scripts/build_pysparql_generate.sh        # exports the pinned commit (PYSPARQL_GENERATE_COMMIT),
                                            # from ../pysparql-generate or the public repository
./scripts/fetch_testcases.sh                # RML test suites, rml2sparql-generate, gtfs-bench, pinned
./scripts/fetch_engines.sh                  # released engines, pinned, checksums verified
                                            # (SPARQL-Generate, RMLMapper, RPT, SPARQL Anything,
                                            # FlexRML, BURP, RMLStreamer, ShExML, Node.js, RocketRML,
                                            # Apache Jena for the fingerprints, rdf-canonize)
python3 scripts/gtfs_mappings.py            # only after a change of the GTFS mapping: the ShExML mapping,
                                            # and workloads/gtfs-inverted/ (RML, ShExML, SPARQL Anything)
./scripts/capped.sh ./scripts/build_sparql_generate.sh   # optional: ../sparql-generate (HEAD),
                                            # run with KGC_BENCH_SG_JAR=head
```

Memory: `KGC_BENCH_MEM_CAP` (default 20G) caps every engine process, and
`KGC_BENCH_MEM_TOTAL` (default 20G) all of them together; adjust both to the machine.

Run every command from this directory (`python -m harness.<module>`).

## 1. RQ1 — conformance

```sh
python -m harness.conformance                       # every suite, every mode, sg-java and sg-java-2.1.0
python -m harness.conformance --engines sg-java pysparql-generate rpt morph-kgc rmlmapper sdm-rdfizer --jobs 3
python -m harness.conformance --suites rml-test-cases --modes translated --only RMLTC0009a-CSV
python -m harness.conformance --suites rml-io rml-fnml --modes rml --engines rmlmapper --no-write
```

The suites (`scripts/fetch_testcases.sh`): rml-test-cases, rml-core, and the RML modules
rml-io, rml-fnml, rml-cc, rml-star, rml-lv. The RML engines (mode `rml`): rpt, morph-kgc,
rmlmapper, sdm-rdfizer, rocketrml, flexrml, burp, rmlstreamer; the Python ones run on the
interpreter of the harness.

Writes `results/conformance.csv`; intermediate files (generated queries, outputs) are kept
under `results/raw/conformance/` (`KGC_BENCH_CONFORMANCE_WORK` for another directory). `RML2SG_DIR=../rml-to-sparql-generate` runs a working
copy of the translator instead of the pinned one.

## 2. RQ3 — performance

Data:

```sh
./scripts/gtfs_data.sh 1          # GTFS-Madrid-Bench, generated in Docker (VIG)
./scripts/gtfs_data.sh 10
./scripts/gtfs_data.sh 1 --from /path/to/csvs   # or import CSV files generated before
./scripts/fetch_kgcw.sh           # KGCW Challenge 2024 (4.5 GB): its GTFS-Madrid-Bench data
for n in 100 1000; do             # at scales 1, 10, 100 and 1000, imported the same way
    ./scripts/gtfs_data.sh $n --from data/kgcw-2024/track2/gtfs-madrid-bench/scale_$n/data/shared
done
```

The synthetic workloads (`nested-json`, `nested-xml`, `flat-csv`) are generated by the
harness, deterministically (fixed seeds).

```sh
python -m harness.perf --engines all --workloads all                # every workload, default scales
python -m harness.perf --workloads gtfs --scales 1 10 --runs 3 --timeout 600
python -m harness.perf --workloads gtfs-inverted   # the GTFS data, IRI-valued branches inverted
python -m harness.perf --campaign c1 ...    # tag the rows; rerun the same command to resume
python -m harness.report                                            # results/results.md
```

Outputs are written under `KGC_BENCH_WORK` (default `results/tmp/perf`), fingerprinted and
deleted (README, "Output check and disk space"): one output at a time is on disk, plus the
spill files of its sort. Free space needed there: 1 GB at GTFS scale 1, 2 GB at 10, 10 GB at
100, 100 GB at 1000 (RMLStreamer: up to about 31 GB of partial output at scale 1, deleted).

## 3. The whole campaign

`scripts/campaign.sh [ID]` runs, on a quiet machine, the conformance and the performance
workloads of the engines of `ENGINES` (default `pysparql-generate`), then the report,
and commits the results. Every run has the same limits: 16 GB of memory
(`KGC_BENCH_MEM_CAP`) and 10 min of wall time (`LIMIT_TIME_S`); a run over a limit is not
viable, recorded, never replayed, and the engine is not tried at a larger size. The
campaign is resumable: run the same command again; a finished step is skipped, a measured
(workload, scale, engine) is not run again whatever its status, and a failed step is not
retried unless its stamp `results/campaigns/<ID>/<step>.failed` is removed. `DRY_RUN=1`
runs every step at its smallest size into `results/dry-run/<ID>/`, without committing.

For pysparql-generate alone: 1 to 2 h, at most 12 (workload, scale) pairs × 3 runs × the
time limit; memory: the limit for one run, `KGC_BENCH_MEM_TOTAL` (20 GB) for all.

```sh
scripts/campaign.sh 2026-11-08
ENGINES="pysparql-generate sg-java sg-java-translated" scripts/campaign.sh 2026-11-08
```

Options of a campaign on a dedicated machine (environment, or `planned.env`):

- `KGC_BENCH_MEM_CAP=24G KGC_BENCH_MEM_TOTAL=24G`: the memory limit of one run (Java heaps:
  75 %, 18 GB) and of all the campaign's processes;
- `LIMIT_TIME_S=600 LIMIT_TIME_S_AT="1000=3600"`: the time limit of a run, and another
  one at a scale (each row of `perf.csv` records its limit, `time_limit_s`, against which
  its viability is judged);
- `KGC_BENCH_CPUS=2-11`: the CPUs the engines run on (`taskset`), the others left to the
  services of the machine; recorded in `machine.json` (`cpus_allowed`);
- `KGC_BENCH_PUBLIC_LOG=<file>`: a public progress log, appended, one short line per event
  (campaign start and end, steps, waiting for a quiet machine, each run started and
  finished with its status, median time and peak memory, each output check, the morning
  stop), without any local path, user or host name (`harness/publiclog.py`).

## 4. The translator, A/B

```sh
scripts/ab_translator.sh flat-csv:1000 gtfs:10 kgcw-records-1M:1   # A: pinned, B: ../rml-to-sparql-generate
```

runs the pinned translator (A) and a working copy (B) in the order A B B A on each
workload, with the translated-query engines (SPARQL-Generate and pysparql-generate), one
run at a time under the run limits, and appends every run to `results/translator-ab.csv`
(time, peak memory, distinct triples: B must give the triples of A).

## 5. Validity notes

- Timings depend on the machine and on its load; `results/machine.json` records both. The
  numbers in `results/results.md` were measured while other jobs ran: provisional.
- The hand-written SPARQL-Generate and SPARQL Anything queries are written to have the
  semantics of the official mapping (empty cells are null, joins are inner joins, IRI
  values are percent-encoded); the output check enforces it at the smallest scale.
